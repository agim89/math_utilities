# Repository File Guide

Quick reference for key files and directories in this project.

- cmake/mylibConfig.cmake.in
  - Template for the CMake package config generated by Conan/CMake so consumers can `find_package(mylib CONFIG)`.
  - Exposes targets and includes pointing at the installed package layout.

- consumer-test/CMakeLists.txt
  - Minimal consumer project that locates the installed `mylib` package and builds a small executable.
  - Exercises the generated CMake config files to ensure downstream consumption works.

- consumer-test/main.cpp
  - Simple consumer app that includes the installed headers and calls `mylib::sum`, proving the package can be found, linked, and run via the generated CMake config.

- include/
  - Public headers for the library (exported API). Downstream projects include from here after installing the package.

- tests/
  - Unit tests for the library, built and run by the test workflow/ctest.

- .clang-format
  - Coding style configuration used in CI (build-test workflow runs clang-format check against this).

- CMakeLists.txt
  - Top-level CMake build definition for the library and tests; drives configuration, targets, and install rules.

- conanfile.py
  - Conan 2 recipe defining the package metadata, build instructions, dependencies, and package layout.

## CI/CD Workflows

### label-verify.yml + build-test.yml (verify flow)

- **label-verify.yml** (math_utilities/.github/workflows/label-verify.yml)
  - Trigger: PR labeled with `verify` (while PR is open).
  - Jobs:
    1. `get-version`: reads VERSION from file and outputs it.
    2. `integration-test`: calls shared `consumer-verify.yml` to install RC `mylib/X.Y.Z-dev-<sha>` from `conan-rc` and run consumer test.
  - **Purpose**: Test an existing RC package from the remote without building/uploading a new one.

- **build-test.yml** (shared-workflows/.github/workflows/build-test.yml)
  - Called by PR checks workflow (pr.yaml).
  - Matrix: ubuntu/macos/windows with profiles linux/macos/windows.
  - Steps: install tools (clang-format, cmake, ninja); clang-format check; conan profile detect/install; cmake configure via presets; build; run ctest.
  - **Purpose**: Verify code format, build, and unit tests pass on all platforms before any label is applied.

**Verify flow**:
1. Open PR → pr.yaml runs build-test.yml (format check + cross-platform build/test).
2. Add `verify` label → label-verify.yml runs consumer-verify.yml (installs existing RC from conan-rc, builds consumer-test, runs executable).
3. No new package is built or uploaded; tests rely on a pre-existing RC in conan-rc.

---

### label-publish.yml (publish flow)

- **label-publish.yml** (math_utilities/.github/workflows/label-publish.yml)
  - Trigger: PR labeled with `publish` (while PR is open).
  - Jobs:
    1. `get-sha`: reads VERSION, calculates short git SHA, outputs `version`, `short_sha`, and `rc_version` (X.Y.Z-dev-<sha>).
    2. `rc-build`: calls shared `conan-package.yml` with `is_rc=true`, `version=X.Y.Z-dev-`, `remote=conan-rc`.
       - **conan-package.yml** builds the RC `mylib/X.Y.Z-dev-<sha>` via `conan create`, checks if base version exists in conan-stable (blocks if yes), runs local consumer-test, uploads to conan-rc.
    3. `integration-test`: calls shared `consumer-verify.yml` to install RC from remote `conan-rc` and run consumer test from installed package.
  - **Purpose**: Build RC, upload to staging remote (conan-rc), verify it works via consumer integration test; enables final release on merge.

**Publish flow**:
1. Open PR → pr.yaml runs build-test.yml (format + build + test).
2. Add `publish` label → validate-version.yml checks VERSION bump; label-publish.yml builds RC via conan-package.yml, uploads to conan-rc, then runs consumer-verify.yml from remote.
3. If all checks pass, merge PR → triggers final release.

---

### release.yml (final release flow)

- **release.yml** (math_utilities/.github/workflows/release.yml)
  - Trigger: PR closed (merged to main).
  - Jobs:
    1. `check-publish-label`: verifies merged PR had `publish` label (or detects new VERSION not yet tagged); sets `should_release=true` if conditions met.
    2. `get-version`: reads VERSION.
    3. `create-release`: calls shared `release.yml` with `version=X.Y.Z`.
       - **shared release.yml** verifies RC `mylib/X.Y.Z-dev-*` exists in conan-rc; builds clean release `mylib/X.Y.Z` via `conan create` (no -dev); uploads to conan-stable; creates git tag `vX.Y.Z` (fails if tag exists); creates GitHub Release with install instructions.
  - **Purpose**: Promote the tested RC to production by rebuilding clean from source, tagging, and publishing to conan-stable.

**Release flow**:
1. PR with `publish` label merges to main → release.yml triggers.
2. Checks if `publish` label present on merged PR.
3. Verifies matching RC exists in conan-rc (safety gate).
4. Rebuilds clean package `mylib/X.Y.Z` from current commit (not a binary copy of RC).
5. Uploads to conan-stable.
6. Tags commit as `vX.Y.Z` and creates GitHub Release.
7. Separately, release-notes.yaml writes Release-Notes/Release-X.Y.Z.md and commits to main.
